Git Strategy - Assignment 4

The project is managed in a private Git repository. Work is separated into feature branches and merged into main using Pull Requests.

Branch Plan

  • feature/mvc-structure - organize server code into models, controllers, routes, views, and config.
  • feature/mongodb - add MongoDB connection and Mongoose post model.
  • feature/delete-post - add the server-side delete route and controller logic.
  • feature/client-fetch - delete posts from the browser with fetch without refreshing the page.
  • feature/readme - document setup, MVC structure, routes, and Git rules.

Pull Request Process

  • Each feature branch is committed separately.
  • A Pull Request is opened from the feature branch into main.
  • The second partner reviews and approves the Pull Request.
  • Only approved Pull Requests are merged into main.

Security Rules

  • .env is not committed.
  • node_modules/ is not committed.
  • Passwords, tokens, API keys, and personal secrets are not committed.
  • The repository remains private.

Testing Before Merge

  • Start the server with npm start.
  • Confirm MongoDB connects successfully.
  • Confirm posts load from MongoDB.
  • Create a post and confirm it appears in the feed.
  • Delete a post and confirm it disappears from the page and MongoDB.
  • Refresh the page and confirm the deleted post does not return.
  • Try deleting a missing post and confirm the server returns Post not found.
